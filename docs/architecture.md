# 架构与数据边界

浏览器 → Nginx 同源入口 → Spring Boot / Security / JPA → MySQL 8.4。REST 会话为 HttpOnly、SameSite Strict，写请求要求会话 CSRF。Actuator 仅匿名开放健康检查，无外部翻译请求。

`TranslationProject` 固定语言对与团队，记录当前状态和指定译员、审校。`Segment` 为当前键 / 源文 / 译文 / 上下文 / 字符上限；`SegmentRevision` 保存每次源文变更、翻译与审校内容；`GlossaryTerm` 在开始时冻结；`Delivery` 保存发布时完整 JSON、双语 CSV 及 JSON SHA-256。后续编辑不修改历史交付。业务键归档保留历史，重新导入同键复用原记录且重新审校。

管理权限与数据范围同时检查。ALL 为全部团队，DEPARTMENT 为账号当前团队，ASSIGNED 为项目负责人、指定译员或审校。账号与角色、菜单、团队、平台字典和参数由数据库持久化，管理接口另要求 ALL；界面隐藏按钮不是权限判断。翻译接口另检查指定译员，审校接口另检查指定审校和编辑者不是本人，管理员也不能冒充别人审校。

每次请求重新读取账号、角色、团队及密码指纹。账号/团队停用或密码重置使旧会话失效。账号已指派项目时不能更换团队，防止历史范围漂移。角色可调整，已有审批记录是发生时的身份事实，不会因为角色后来改名被覆盖。停用团队保留历史，ALL 管理员仍可读取其历史项目。

写入先锁主团队行，在低容量实例内串行执行，再比较明确的业务版本。项目状态与源文/配置动作比较项目版本；译文和审校比较文案版本。陈旧请求返回 VERSION_CONFLICT，没有自动重放写入。全局锁是一项吞吐限制，不适用于高并发 SaaS。

项目 DRAFT → ACTIVE；ACTIVE 可暂停为 PAUSED、恢复 ACTIVE。ACTIVE 中所有当前文案独立审校通过才能发布。发布不关单；修改源文或译文使当前审校失效，必须重新审批并发布后才能 CLOSED。未关闭项目可带原因 CANCELLED。CLOSED/CANCELLED 不可再编辑。术语只在 DRAFT 管理。已发布版本始终保留。

数据仅在内部 MySQL 中，无上传媒体卷。Flyway V1 创建 15 张应用表及迁移历史表，首次 Bootstrap 创建目录与私有管理员；没有内置测试业务。自动验收脚本通过实际 HTTP 在空库创建明确 TEST 数据。
