# 操作手册

1. 管理员进入“登录账号”，创建项目经理、译员、审校。密码独立设置为 12–72 字节且含大写、小写和数字。译员和审校必须为不同账号。系统保留最后一个启用的完整 ALL 管理员；普通项目经理不能管理系统账号。
2. 新建项目，填团队、源/目标语言标签（例如 en / zh-CN）、软件平台、指定译员与审校、交付日期。一个项目对应一个目标语言；其他目标语言另建项目。源语言与目标语言不能相同，后续不可更换团队/语言对。
3. “导入原文”选择 UTF-8 的扁平 JSON 文件或粘贴 JSON，先验证预览再确认。只允许字符串值，512000 字节、默认最多 2000 条、键名 160 字符；拒绝嵌套、数组、重复或仅大小写不同键。整批验证不通过时不写任何记录。勾选替换全部时缺失键归档；不勾选则合并更新。
4. 可逐条新增原文，编辑原文/上下文和字符上限（0 不限），或归档键。键名只允许 ASCII 字母、数字、`_ . : / -`；现有键稳定，换键通过导入新键并归档旧键。上下文和字符上限随源文更新，审批失效；JSON 导入将这两项恢复默认。原文和译文支持 4000 UTF-16 单元，保留首尾空白、换行与制表符，不接受空白原文或无效 Unicode。
5. 添加术语，开始翻译后术语冻结。术语核查采用区分大小写的字面包含，不识别语法变化或词形；可留审校原因接受提示。修改冻结术语需要另建修订项目，不能悄悄改变正在审批的规则。
6. 译员在“我的译稿”打开指派项目，按原文、上下文和字符上限填写译文，保存草稿或保存并送审。精确匹配建议仅取同团队、同语言对、自己可见项目的当前已审批译文；人工应用后仍需重新送审。搜索覆盖键名/原文/译文/上下文，筛选当前状态。未保存译文切换键或导航会提醒放弃；断网写入结果未知时先刷新核对。
7. 审校在“审校队列”打开指派项目，核对送审译文；通过或带修改意见退回。变量 `{name}`、`${name}`、`{{name}}`、`%s / %d / %i / %f`、`%1$s` 等位置型、`%(name)s` 等命名 printf 的名称及次数必须一致，`%%` 为转义百分号。空译文、变量差异或超过字符上限阻断审批，不可豁免。数字差异、原译文相同和术语缺失为提示，审校确认后须记录具体原因。
8. 管理员也不能批准自己编辑的版本；只有项目指定译员可编辑译文，指定审校可处理译文。规则不判断翻译语义，不支持完整 ICU MessageFormat、复数/性别规则、HTML/XML 标签结构、全部 printf 格式。此类文案必须人工核对，复杂资源格式应另行适配。
9. 项目经理在全部文案通过审校后发布交付版本，填版本名，下载精确语言 JSON 和防公式双语 CSV。JSON SHA-256 可验证文件一致。CSV 为查阅/表格格式，公式前缀会加单引号，不能将其当作精确导回格式。后续修改不覆盖旧交付；更新全部审校和交付后可关单。
10. 管理端维护团队时区、平台字典、菜单名称/排序/启用、角色权限及参数。菜单/权限/参数代码是固定系统目录，不支持任意新增路由或执行脚本；账号、团队和字典停用保留历史。报表日期按项目团队 IANA 时区判断临期或逾期，导出范围与界面访问范围一致。操作记录不包含密码、会话或完整文案；详细文案证据在项目修订中。

“发布”只生成数据库中的交付快照，不会自动推送 Git、上架应用商店或发送邮件。没有机器翻译、付款、消息发送或外部客户资料。
